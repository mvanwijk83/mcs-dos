  0. Introduction
----------------------------------------
MCS-DOS is a simple MS-DOS-inspired
command shell designed to work on an
unexpanded Commodore 64, Commodore 64
Ultimate, Commodore 128 in C64 mode,
and on emulators. It provides familiar
prompts, commands, syntax and system
messages to perform disk operations. It
also supports rudimentary batch
scripting.

MCS-DOS was created for fun and novelty,
and the author makes no claims as to its
real-life usefulness.

Disclaimer: this software is provided

https://github.com/mvanwijk83/mcs-dos


  1. Features and limitations
----------------------------------------
MCS-DOS is merely a command shell, not a
full operating system. It attempts to
bring the classic DOS look and feel to
the C64 as much as possible:

* Many familiar commands and utilities
  are implemented.
* Configuration via AUTOEXEC.BAT and
  CONFIG.SYS.
* Some batch file support.
* Supports multiple attached drives and
  multiple models (1541, 1571, 1581).
* Drives can be optionally displayed and
  addressed with DOS-style drive
  letters.
* Simple built-in text editor.
* Quality-of-life features such as
  command history and filename auto-
  completion.
* Environment variables.
* Output redirection to files.
* File printing.
* Command help easily accessible from
  the shell.
* Customizations including prompts,
  colors and custom character sets.

A full-featured MS-DOS clone is not
truly possible due to C64 limitations,
and architectural differences with IBM
PC-compatibles. Some notable limitations
and omissions include:

* No directory support.
* Automatic return from native programs
  depends on their exit implementation,
  if any.
* Batch files do not support variables,
  conditionals, labels, or parameters.
* No piping, output redirection does not
  support printers.
* Duplicating disks between different
  drive types is currently not
  supported.
* Due to the shell's mixed-case mode,
  half of PETSCII's graphics characters
  do not display correctly.

Future versions may address these and
other shortcomings where possible.


  2. Development notes
----------------------------------------
  Technology
MCS-DOS was written in C and compiled
with Oscar64. It has been tested on a
C64 Ultimate and in VICE. Automated
unit and regression testing was
implemented with Node.js.

  Background
MCS-DOS started as a simple throwaway
project for personal entertainment,
motivated by a geeky impulse to see a
believable DOS-style environment running
on the C64, no matter how simple and
limited; and an opportunity to test
GPT-6. Once things started to look
genuinely usable, it became a continuing
effort to keep improving and polishing
it.

  AI disclosure
While MCS-DOS has been designed in
detail by human creativity and
intellect, OpenAI's Codex and GPT-6
(Astra) LLM have been extensively used
to assist with implementation, review,
and automated testing and building. All
generated code has been manually
reviewed and modified where necessary.
Additionally, all functionality has been
manually tested on hardware.

  4. Running MCS-DOS
----------------------------------------
  Startup
If you have a physical EasyFlash cart-
ridge, start MCS-DOS from the menu. The
.CRT image must have been flashed onto
the cartridge first.

In VICE, use File -> Attach cartridge
image. On an Ultimate, enter the file
browser and run the .CRT.

  Boot configuration
If an AUTOEXEC.BAT is present, it will
execute before you arrive at the shell
prompt. It is not present by default;
create it or rename the sample file.

See chapter 7 for more information on
how to configure and customize the
shell via environment variables.

By default, MCS-DOS looks for
AUTOEXEC.BAT in the writable area of
the cartridge image. A CONFIG.SYS can
be created to change this behavior,
which will be processed first. The
following directives are available:

BOOTDRV=drive[,...]
  Specify one or more drives where
  MCS-DOS should seek AUTOEXEC.BAT, in
  that order. For example, BOOTDRV=8,0
  will look for AUTOEXEC.BAT on the
  first disk drive (device 8) first, and
  then on the cartridge (device 0) if it
  wasn't found. If BOOTDRV is omitted,
  device 0 is assumed.

LDAUTOEX=0|1
  Whether AUTOEXEC.BAT should be ran at
  all. LDAUTOEX=0 will disable it;
  BOOTDRV would then not take effect
  either. The default value when omitted
  is 1 (i.e. load and run AUTOEXEC.BAT).

The directives are case-insensitive and
whitespace is ignored.

  Safe mode
You can press RESTORE on the boot screen
to enter a "safe mode"; it will skip
processing of the startup files,
applying default settings instead. This
can be useful to correct mis-
configurations that render your shell
unusable.

  Cartridge storage
64,000 bytes of writable storage is
available on the cartridge image. It is
the default location for your startup
configuration files and where the
bundled documentation resides. However,
nothing stops you from storing anything
else you may want to keep there. Indeed,
if your boot script references resources
not bundled with MCS-DOS, you might want
to copy them there instead of relying on
an external disk.

A custom journaling file system is
implemented to allow for fast file
operations while reducing physical flash
writes. It however requires occasional
compaction to reclaim space from stale
metadata records and deleted content.
This happens automatically, which is
noticeable as a slowdown during writes
when it occurs. Compaction can also be
forced via CHKDSK /C.

Changes to the writable area of the
cartridge image persist automatically on
a real EasyFlash cartridge. In VICE, you
may have to enable writeback settings.
On an Ultimate, you need to press F1 in
the Ultimate menu, go to Power & Reset,
and select Save Cartridge. This updated
image must be loaded next time you use
MCS-DOS.


  5. Using the shell
----------------------------------------
  The command prompt
See chapter 6 for a list of supported
commands. The command interpreter is
case-insensitive, and treats spaces
before switches as optional. For
example, DIR/W and DIR /W both work.
The maximum full length of a command,
including parameters, is 64 characters.

You can use CRSR LEFT/RIGHT to move
within the command text. Typing inserts.

When specifying filenames as command
parameters, double-quote them if they
contain spaces or a slash. You can use
the Commodore key to cycle through file
names stored on the active disk and to
autocomplete. (Rely on this feature
especially when having to enter file
names containing certain PETSCII
graphics characters that do not display
correctly in the shell's mixed-case
mode; the auto-complete internally
preserves the byte-correct original
filename.)

Command history is retained for the last
ten entries. Use CRSR UP/DOWN to cycle
through the last ten issued commands.

The appearance of the command prompt can
be configured with SET PROMPT in
AUTOEXEC.BAT to be applied at startup.
See chapter 7 for more details.

RUN/STOP aborts operations where
possible (think of it as the Ctrl-C
equivalent).

  Running programs
Native C64 programs or batch files can
be started from the shell using the RUN
command. Batch files run fully within
the shell and return control after
completion. Native program return is
not guaranteed; it depends on their
own exit implementation (if any), and
whether they preserve BASIC return via
$0302-$0303 and don't overwrite $C000–
$C1FF, which contains the MCS-DOS
shell re-entry hook.

The current shell state is saved prior
to program execution, and restored upon
return to the shell. If restoration
fails for some reason, MCS-DOS defaults
will be applied.

Cartridge reset is still available as
a return option, although it will
restart MCS-DOS in its entirety.

  Using Commodore BASIC
The BASIC command can be used to enter
the C64 BASIC environment. MCS-DOS
installs a return wedge that allows
you to return to the shell by typing
SHELL at the BASIC prompt (provided
that any programs run within BASIC
do not overwrite $C000–$C1FF). As
with native program execution, shell
state is restored upon return.

  Devices
The shell supports standard C64 device
numbers as well as DOS-style letter
aliases: drive 8 is A, drive 9 is B,
etc. Display is determined by the
DRIVEIDS environment variable (see
chapter 7). Typing a drive number or
letter followed by a colon (e.g. 8:, A:)
will select that drive as the current
one.

Similarly, for print commands both
drive numbers 4 and 5 can be specified,
or DOS aliases LPT1 and LPT2.

Datasette (tape) support is present in
the form of the TAPECOPY command which
can be used to transfer files from tape
to disk or cartridge. Program (PRG) or
data (SEQ) files of up to 44 kb can be
transferred, assuming no custom loader
is used on the source tape.

  Redirection and piping
Command output redirection to file is
supported (see chapter 9). Input
redirection, printer redirection and
piping are not supported.

  Theming
The appearance of the shell (colors,
character set, prompt format, drive
identifiers) can be customized via
environment variables. See chapter 7
for more information.


  6. Commands
----------------------------------------
MCS-DOS features familiar commands from
classic MS-DOS, as well as a few of
its own. A list of supported commands
can be viewed from within the shell by
entering the HELP command. 

Help on a specific command can be
viewed by typing "HELP command" or
"COMMAND /?".

Wildcards * and ? work for most file
operations (where they make sense).

drive:
  Switches to a drive to operate on.
  Native C64 drive numbers and DOS-style
  drive letters (with 8=A, 9=B, etc.)
  are both recognized.

ATTRIB [+L | -L] [[drive:]filename]
  Displays or changes file attributes.

BASIC
  Starts the C64 BASIC environment.

BEEP [duration]
  Plays a SID beep.

CHKDSK [drive:] [/V] [/C]
  Checks a disk and returns a status
  report.

CLS
  Clears the screen.

COPY source destination [/P]
COPY source1+source2[+...] destination
  Copies a file to another location,
  or combines files on the same disk.

DEL [drive:]filename [/P]
DELETE [drive:]filename [/P]
ERASE [drive:]filename [/P]
  Deletes one or more files.

DIR [drive:][pattern]
    [/B /L /Osortorder /W]
  Displays a list of files on a disk.

DISKCOPY source: destination:
  Copies the contents of a disk to
  another of the same drive type.
  Source and destination drives must
  be of the same type.

DISKID [drive:] [id]
  Changes the drive's two-character ID.

DISKINIT [drive:]
  Resets disk drive state and forces a
  reread of the directory.

ECHO [ON | OFF]
ECHO [message]
ECHO.
  Displays messages, or turns command-
  echoing on or off.

EDIT [filename]
  Edits one screen of text.

FIND [/V] [/C] [/N] [/I] "string"
     [[drive:]filename]
  Searches for a text string in a file.

FORMAT drive:
  Formats a disk.

HELP [command]
  Displays help on MCS-DOS commands.

LABEL [drive:] [label]
  Creates, changes, or deletes the
  volume label of a disk.

MEM
  Displays the amount of used and free
  memory in your system.

MOVE source destination [/P]
  Copies the source file to the
  specified destination, then deletes
  the source.

PAUSE
  Suspends processing of a batch program
  and waits for a key to resume.

PRINT filename [4:|5:|LPT1|LPT2]
  Sends the contents of a file to a
  printer.

REBOOT
  Reboots the environment.

REM [comment]
  Records comments in a batch file.

REN filename1 filename2
RENAME filename1 filename2
  Renames a file on the same disk.

RUN filename [/A address]
  Executes a program.

SET [variable=[string]]
SET /ENV
  Displays, sets, or removes
  environment variables.

SPLASH
  Shows the MCS-DOS splash screen.

SYSINFO
  Provides technical information about
  your computer.

TAPECOPY [filename] [drive:]
  Loads and transfers one or more files
  from tape to disk.

TYPE filename [/H:n | /T:n | /HEX]
  Displays the contents of a file.

VER
VERSION
  Displays the MCS-DOS version and
  copyright information.

VOL
  Displays the volume label (disk name)
  and disk ID, if they exist.


  7. Environment variables
----------------------------------------
Several environment variables are
available to configure shell layout and
behavior. Set these in your AUTOEXEC.BAT
to customize your experience.

Syntax:
  SET NAME=VALUE

The settings are case-insensitive, and
whitespace is ignored. Setting variables
with unsupported names is not rejected;
however, they will not do anything.

Variable names have a maximum length of
8 characters. Values can be up to 32
characters long.

There are 512 bytes available to store
environment variables into. If this is
exceeded, SET will display an error
message.

Environment variables supported out of
the box are:

CHARSET
  Specifies a custom character set to be
  used by the shell. A matching .CPI
  file must be present on the startup
  disk. If omitted or empty, the shell
  uses the default C64 ROM font. A
  standard MCS-DOS distribution ships
  with CGA.CPI for added PC flavor.
  Extra character sets can be downloaded
  separately from the source code
  repository. Only alphanumeric and
  punctuation characters are replaced;
  PETSCII graphics characters are
  retained. To apply a custom character
  set, use SET CHARSET=NAME, where NAME
  matches a .CPI file minus extension.

COLOR
  Specifies the shell colors. Use the
  following syntax:
    SET COLOR=c1,c2,c3
  Where:
    c1 = foreground (text) color
    c2 = background color
    c3 = border color

  Possible color values are 0-15,
  matching the standard C64 color
  numbers. If COLOR is omitted or
  invalid, the default is applied:
  light grey on a black background
  and border (15,0,0).

DIRCMD
  Specifies default parameters to be
  used by the DIR command when it is
  invoked without any. For example,
  DIRCMD=/O/W will in this case force
  DIR to always list a directory in
  alphabetic order and in wide format.

DRIVEIDS
  Specifies whether to display standard
  C64 drive numbers, or DOS-style drive
  letters, where drive 8 is A, drive 9
  is B, etc. Valid values are "C64" and
  "DOS". If empty or not specified, C64
  is used. Note that both forms are
  always accepted by shell commands,
  regardless of the display setting.

  The cartridge storage volume is
  always identified as "0", regardless
  of DRIVEIDS.

PROMPT
  Specifies the format used for the
  command prompt. The format string can
  contain literal text and the following
  special codes:

    $B  | (pipe symbol)
    $C  : (colon)
    $D  Drive letter
    $G  > (greater-than sign)
    $H  \ (backslash)
    $N  Drive number
    $P  Drive identifier according to
        the DRIVEIDS variable
    $Q  = (equal sign)
    $R  Line break (RETURN)
    $S  Space
    $V  MCS-DOS version number
    $$  Dollar sign

  Example:
    SET PROMPT=READY.$R$D$C$G
  Configures:
    READY.
    A:\>

  The default setting is $P$C$G, which
  yields A:> or 8:>, depending on
  DRIVEIDS. The format codes are case-
  insensitive.


  8. Output redirection
----------------------------------------
The screen output of certain commands
can be redirected to a file. Supported
are CHKDSK, DIR, ECHO, FIND, MEM and
TYPE.

To redirect output to a new file, use
the > operator. If the file already
exists, it will be overwritten without
asking confirmation. Example:
  DIR /B > FILES.TXT

To append to an existing file, use >>.
Example:
  ECHO Hello world >> NOTES

Drive prefixes work, e.g.:
  MEM > 9:"MY MEMORY.TXT"
  CHKDSK >> A:DISKSTATS.TXT

Output has no screen wrap or pagination.

Redirection to printers is currently
not supported. A workaround is to
redirect to a file, and then use the
PRINT command to print that file.


  9. EDIT tool
----------------------------------------
The EDIT tool provides a 40 columns by
24 rows surface of editable text (the
bottom row is occupied by a status bar).
You can freely use the cursor keys to
navigate around the screen. Typing
overwrites.

Edit keys:
  RETURN
    Moves to the next row.
  INST/DEL
    Deletes the previous character.
  SHIFT+INST/DEL
    Inserts a space after the current
    position.
  CTRL+INST/DEL
    Inserts a blank line before the
    current one.
  CLR/HOME
    Moves the cursor to the top left
    corner.

The status bar shows the current line
and column, separated by a colon, as
well as the filename if applicable.

When you are done editing, press RUN/
STOP. EDIT will ask if you want to save
the file to the current disk, and
prompts for a filename if you didn't
already specify one when invoking the
command.

The saved file will contain carriage
return line endings, and trailing row
spaces and unused bottom rows are
trimmed.


  A. Batch scripting
----------------------------------------
Batch files can be created from within
the shell using the EDIT tool (or
externally, if you prefer). They can be
executed from the shell with the RUN
command. Batch files must have a .BAT
extension as part of their file name to
be recognized as such.

ECHO OFF works, including "@" to
suppress the echo of that line. There
are no variables, conditionals, labels,
parameters, or any other program-like
constructs; batch files are strictly a
sequence of MCS-DOS commands. They also
can't call other batch files.

MCS-DOS supports AUTOEXEC.BAT. If it is
present on device 0 (or a device chosen
by CONFIG.SYS), it runs at startup.
Pressing RESTORE on the boot screen will
run MCS-DOS in "safe mode"; it skips
execution of AUTOEXEC.BAT.
